SECTION 6 -- CAN THE LAST BAR OF A SESSION PARTICIPATE?
==============================================================================
Static analysis:

v601 backtest_one:
  - signal is built by build_tag as close.pct_change(6) * 100 < q25.
  - entry requires _next_session_first_bar(df, t) == False.
  - if t is the last bar of a session, _next_session_first_bar returns True,
    therefore open_position returns None, no trade is created.
  - Therefore the last bar of a session cannot create a trade entry.
  - It can still, in principle, be assigned a signal value in build_tag,
    but that value never leads to an entry.

v600 build_forward_labels:
  - future indices are collected only while
    sk_5m.iloc[j] == session. Stop at first cross-session bar.
  - if h > max_available, label is NaN and label_partial_window_H = True.
  - Therefore forward windows never cross sessions.
  - The last few bars of a session may have partial windows for large h.
  - Those are marked in the data and would be dropped in any H4
    implementation that respects the same rule.

Controls and baselines:
  - there is no separate control-set construction in v600/v601.
  - in a future H4 implementation, controls are defined by H4 spec,
    not by v600/v601. The spec must state whether the last bar of a
    session can be a control. Currently UNRESOLVED in existing code.
